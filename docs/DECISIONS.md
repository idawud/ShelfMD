# Architecture Decision Records

## ADR-001: Using Tauri v2 over Electron

**Status:** Accepted

**Context:** We needed a cross-platform desktop runtime to host the SvelteKit UI.

**Decision:** Use Tauri v2.

**Rationale:**
- Bundle size: Tauri produces ~4 MB installers vs Electron's ~120+ MB because it leverages the OS WebView (WebView2 on Windows) rather than bundling Chromium.
- Native WebView2: On Windows 11 this is always present and hardware-accelerated; no separate distribution concern.
- Rust safety: Backend logic benefits from Rust's memory safety guarantees, preventing entire classes of security bugs common in Node.js native addons.
- Performance: Lower memory footprint and faster startup than Electron.

**Trade-offs:** Requires Rust knowledge; WebView2 rendering may differ slightly from Chromium on some CSS features.

## ADR-002: All path logic in Rust

**Status:** Accepted

**Context:** Link resolution in Markdown books requires resolving relative paths, handling case-insensitive Windows paths, extensionless links, and wiki-style `[[Name]]` links.

**Decision:** All path normalisation and resolution runs in Rust (`resolver.rs`), called via Tauri IPC from the frontend.

**Rationale:**
- JavaScript `path` module is POSIX-oriented; it does not handle Windows drive letters, UNC paths, or case-insensitive lookup reliably.
- `dunce` + `path-clean` in Rust handle Windows quirks (drive letter canonicalisation, `\\?\` prefixes) correctly.
- Keeping path logic pure (no I/O in unit tests) makes it easy to unit-test edge cases without spinning up a browser.

**Trade-offs:** Every link click incurs an async IPC round-trip (~0.1 ms on localhost IPC; imperceptible).

## ADR-003: SQLite via rusqlite WAL mode

**Status:** Accepted

**Context:** We need persistent storage for reading progress, bookmarks, library metadata, and session state.

**Decision:** Embed SQLite using `rusqlite` with `bundled` feature; enable WAL journal mode.

**Rationale:**
- Zero dependency: no separate database server to install or update.
- WAL mode allows concurrent readers without blocking writes, which matters for background watcher writes during reading.
- Works correctly inside MSIX sandbox via app data directory redirection — no hardcoded paths.
- `rusqlite` with `bundled` compiles SQLite from source, avoiding system library version mismatches.

**Trade-offs:** Slightly larger binary due to bundled SQLite (~600 KB). No multi-process access (acceptable for a single-user desktop app).

## ADR-004: markdown-it over remark

**Status:** Accepted

**Context:** We need a Markdown renderer that supports GFM, footnotes, task lists, KaTeX, Mermaid, source-position tracking, and link interception.

**Decision:** Use `markdown-it` with plugins.

**Rationale:**
- Synchronous rendering API: markdown-it renders synchronously, which simplifies the reactive Svelte component (`$effect` can await a simple Promise wrapper).
- Source-pos support: `markdown-it` has a built-in `source_map` mechanism used for reading-memory scroll anchoring.
- Plugin ecosystem: `markdown-it-footnote`, `markdown-it-task-lists`, and others are well-maintained.
- remark/rehype's async plugin pipeline adds complexity for our use case and has a larger bundle footprint.

**Trade-offs:** markdown-it is not spec-identical to CommonMark in all edge cases; acceptable for our target use case of reading AI-generated and developer-authored books.

## ADR-005: Wiki links `[[Name]]` resolved by filename anywhere in book

**Status:** Accepted

**Context:** Many Markdown books generated by tools like Obsidian, Logseq, or custom pipelines use `[[Filename]]` wiki links without specifying a full path.

**Decision:** Resolve `[[Name]]` by scanning the book's file tree for any file whose stem matches `Name` (case-insensitive on Windows).

**Rationale:**
- Best serves the primary use case: reading a pre-generated multi-file book where file names are the natural identifiers.
- Authors don't want to maintain full relative paths when reorganising chapters.
- Matches Obsidian's resolution behaviour, the most common source of such books.

**Trade-offs:** Ambiguous if two files share the same name in different directories. Resolution: first match wins (depth-first, alphabetical); a future warning toast will notify of ambiguity.
